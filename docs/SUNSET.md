# 上游失效 / 项目停更时的处置

这个项目依赖 WorkBuddy 未公开的上游协议与登录凭据格式。**上游随时可能改动协议、收紧风控或停止该路径**；历史上已经发生过同类项目删库、停更和账号批量 403。这里写清楚“真失效了怎么办”，避免把时间浪费在反复重试上。

## 先判断是哪一类失效

| 现象 | 含义 | 处置 |
|---|---|---|
| 启动失败 / `import failed` | 插件与 dsh 版本或包名不匹配 | 按 [INSTALL.md](INSTALL.md) 重装；看 crash log 的具体 import 行 |
| 401 + 登录文件正常 | 本地令牌不一致，或登录态需要刷新 | 读运行期数据目录的 `bridge-token`；重新登录桌面端/插件 |
| 403 / 11140 / 账号被禁用 | 账号级拒绝，不是请求参数问题 | **停止反复重试**；换回官方客户端确认账号状态；不要尝试绕过 |
| 11128 持续出现，降级全失败 | 上游通道模板/身份校验升级 | 用 `doctor --bundle` 和 bridge 日志提 issue；不要原样重发 |
| 6004 / 额度耗尽 | 账号配额用尽 | 等重置/换自己的账号；本桥不做多账号池化 |
| 429 持续 | 频率限制（可能按出口 IP） | 降频；`WORKBUDDY_RATE_LIMIT_RPM` 设保守值；不要狂重试 |
| 模型目录为空但 `/health` 正常 | 上游目录端点变更 | 看 `upstreamShape.sources`；提 issue，附诊断包 |

## 退回官方客户端

1. 停止桥/控制台/插件，避免后台签到或刷新继续请求上游。
2. 在 WorkBuddy 官方客户端里正常登录使用；本项目的凭据文件只读，不会影响桌面端。
3. 如果做过「一键接入」，在控制台「客户端接入」里点「撤销接入」，把客户端配置还原到接入前。

## 数据与配置在哪

默认 `%USERPROFILE%\.workbuddy-bridge\`：

- `state.json`：账号钉住、签到偏好、排序/隐藏
- `usage.jsonl`：本地用量账本（元数据）
- `quota-history.jsonl`：余额快照
- `media-tasks.json`：媒体任务元数据
- `bridge-token`：本地回环令牌
- `credentials/`：插件登录凭据（DPAPI + AES-GCM）

这些是**本项目自己的数据**，不含上游明文凭据；需要备份/迁移时整目录复制即可。删除它不会删 WorkBuddy 客户端登录态。

## 项目停更时

- 最后一个可用版本以 GitHub Releases 为准；保留对应 tgz，必要时可离线重装。
- 源码 MIT；可自行 fork，但请继续遵守「单账号、仅本机、不绕风控、不导出凭据」的边界。
- 不要从非官方渠道下载二次打包的「增强版/破解版」——无法审计，且可能窃取账号。

## 不要做的事

- 不要因为失效去尝试多账号、代理池、伪造设备指纹或破解客户端密钥。
- 不要把控制台/桥绑到 `0.0.0.0` 或通过内网穿透暴露。
- 不要在公开 issue 或 Discussions 里贴令牌、Authorization 头、登录文件、账号 UID 或完整对话。
