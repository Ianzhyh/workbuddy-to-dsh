# WorkBuddy 控制台精致工程设计规范 (Blue Precision Design System)

> **版本**：v1.1.0  
> **适用范围**：WorkBuddy Local Bridge Web 控制台 (`dashboard/public/`)  
> **核心原则**：纯实色打底 + 单色系微渐变 (Monochrome Sheen)、皇家蓝主调 (Solid Royal Blue)、语义色编码 (Semantic Color Coding)、分层阴影 (Layered Elevation)、严格层级圆角 (Unified Radius Hierarchy)、舒适呼吸节律 (4px/8px Spacing Grid)、优雅微动效 (Physical Micro-Interactions)。

---

## 1. 设计哲学与核心理念

本设计规范摒弃了泛滥、浮夸的多彩渐变与霓虹光晕，回归高质量专业工程工具（如 Linear、Vercel、GitHub Enterprise）的沉稳、严谨与高信息密度美学：

1. **纯正皇家蓝作为唯一主基调**：以经典纯粹的皇家蓝 (`#2563eb` / `#3b82f6`) 贯穿全局，构建强烈的专业工具品牌辨识度与操作视觉重心。
2. **纯实色打底，只在实心色块上用单色系微渐变 (Monochrome Sheen)**：页面背景、面板、文字一律纯实色，严格杜绝一切多彩渐变与霓虹光晕。唯一允许的渐变是**同一色相内的明度变化**（顶部提亮 → 底部归零，见 `--sheen-top` / `--grad-primary`），且只落在实心主色块（品牌块、主按钮、激活 Tab）与图表柱体上 —— 它的职责是给材质一个受光方向，不是装饰。
3. **统一且严谨的圆角层级 (Unified Radius)**：每个元素无论大小，必须严格对齐五级圆角规范（4px / 8px / 12px / 16px / 9999px），杜绝任何散落的随意数值。
4. **克制优雅的物理微交互 (Tactile Motion)**：动效仅用于明确状态变更、空间展开与交互反馈，使用统一的物理惯性缓动曲线 (`cubic-bezier(0.16, 1, 0.3, 1)`)，杜绝拖沓。
5. **层次靠分层阴影，不靠描边 (Elevation by Layered Shadow)**：每个浮起的层用「接触影 + 环境影」两层投影交代高度。只有 1px 描边的界面读起来是「画在纸上的方框」，而不是「浮在背景上的一层」—— 这是界面显平的根本原因（见 2.5）。
6. **颜色要承载语义，不只是好看 (Semantic Color Coding)**：同一排指标卡不能清一色主色。本地 / 远端、健康 / 临期、身份 / 额度，各用各的色相（见 2.4 与 6.4），让人扫一眼就能分组 —— 而不是逐个读文字。

所有边框均采用纯色 1px 极细发丝线（Hairline Border）：

- `--border-subtle` (`#edf2f7` / `rgba(255, 255, 255, 0.04)`): 表格行底线、次级分隔。

| **Promo / 促销** | `#be185d` / `#f43f5e` | `#fdf2f8` / `rgba(244, 63, 94, 0.12)` | `#fbcfe8` / `rgba(244, 63, 94, 0.28)` | 免费模型、限时促销标识 |
| **Info / 信息** | `#0891b2` / `#22d3ee` | `#ecfeff` / `rgba(34, 211, 238, 0.12)` | `#a5f3fc` / `rgba(34, 211, 238, 0.28)` | **远端 / 网络**类指标（上游端点）。第四种语义色，专为「本地 vs 远端」的分组而加 |

> `--info` 是后加的，理由值得记一笔：状态卡原先 8 枚图标**全是同一个皇家蓝**，
> 一眼扫过去分不出「桥进程」（本机进程）和「上游端点」（远端网络）—— 而这两件事
> 出问题时的排查方向完全不同。青与 ok 绿、warn 琥珀、fail 红都不撞，语义不重叠。

## 2.5 阴影与层次 (Elevation)

**每个浮起的层都用两层投影，而不是一层。**

| 层 | 职责 | 特征 |
| :--- | :--- | :--- |
| **接触影 (key)** | 交代元素「贴在哪」 | 短距（1~2px）、小模糊、低透明度 |
| **环境影 (ambient)** | 交代元素「浮多高」 | 长距（10~44px）、大扩散、**负 spread** |

负 spread（`-4px` ~ `-16px`）不是可选项：不加的话大卡片四周会糊出一圈脏边。

| 令牌 | 用在哪 |
| :--- | :--- |
| `--shadow-xs` | 内嵌小控件（下拉、迷你按钮） |
| `--shadow-sm` | 控件悬停 |
| `--shadow-card` | 状态卡、表格壳、抽屉条、告警条 |
| `--shadow-panel` | 主面板容器 |
| `--shadow-drawer` | 浮层：自绘下拉菜单、提示气泡、展开的抽屉 |
| `--shadow-lift` | **可点卡片的悬停抬升**（指标卡、客户端卡）。日常面板**不要**用 —— 整页几十个面板一起浮会变成噪声，而且它们本来也不可点 |

**浅色与深色的做法相反，这是刻意的：**

- **浅色**：纯投影分层。描边交给元素自己的 `border`（悬停时要改颜色），阴影只负责投影 ——
  两者分工明确，也不会和 border 叠成双线。
- **深色**：黑底吃影，所以除了加重投影，**还要保留一圈 1px 亮环**，否则面板边缘会糊成一片。

改这几个令牌要顺手量一次：`node tools\dev\test-viewports.mjs`（阴影不影响布局，
但改令牌时容易连带动到 padding）+ 出一张 `tools\dev\shot-console.mjs` 人工看层次。

## 3. 统一圆角规范 (Radius Hierarchy)

整站严格遵循五级圆角阶梯，杜绝任何中间散落数值：

| 规范级别 | 变量名 | 数值 | 覆盖元素清单 |
| :--- | :--- | :--- | :--- |
| **Micro (微小)** | `--radius-xs` | `4px` | 迷你标签 (`.tag`)、版本角标 (`.brand-badge`)、代码片段 (`code`)、滚动条滑块 (`::-webkit-scrollbar-thumb`)、迷你按钮 (`button.mini`)、详情图标按钮 (`.infobtn`) |
| **Small (小)** | `--radius-sm` | `8px` | 标准按钮 (`button`)、输入框 (`input[type="text"]`)、下拉框 (`select`)、导航选项 (`.nav-tab`)、诊断行 (`.diag-row`)、提示框 (`.notice`)、终端代码块 (`pre.log`) |
| **Standard (标准)** | `--radius` | `12px` | **抽屉栏主外框 (`details`)**、**表格行详情展开抽屉 (`.detail-body`)**、HUD 状态卡片 (`.card`)、表格包裹外框 (`.tablewrap`)、操作工具条 (`.actions`)、模型工具栏 (`.regbar`)、对话输出容器 (`#chatOut`)、账号条目 (`.acct`)、告警栏 (`.alert`) |
| **Large (主面板)** | `--radius-lg` | `16px` | 模块主容器 (`.panel`)、全局大面板包裹外框 |
| **Full (完全胶囊)** | `--radius-full` | `9999px` | 运行状态胶囊 (`.badge`)、快速提问胶囊 (`.quick-pill`)、筛选标签芯片 (`.filterchip`)、进度条槽位与填充条 (`.ptrack`, `.pfill`, `.rank-track`, `.rank-fill`) |

## 4. 间距网格系统 (Spacing Rhythm)

基于统一的 4px / 8px 基础网格系统，提供高信息密度与呼吸感兼备的布局：

```css
--space-1: 4px;   /* 紧凑间隙：图标与文字微距、标签内间隙 */
--space-2: 8px;   /* 行内间距：按钮组间隔、输入框间隙、表单网格小边距 */
--space-3: 12px;  /* 模块内小间隙：工具条内边距、卡片标题与图标间距 */
--space-4: 16px;  /* 标准组件间隙：卡片网格 gap、表格内外边距 */
--space-5: 20px;  /* 结构模块外边距：面板间下边距、主操作条外边距 */
--space-6: 24px;  /* 主面板内边距：panel 内衬填充、大区块间隔 */
--space-8: 32px;  /* 全局段落分界：主要内容区分隔 */
```

### 关键组件间距规范

- **全局页面包裹器 (`.wrap`)**：最大宽度 `1180px`，页面边距 `28px 24px 80px`。
- **面板卡片 (`.panel`)**：内边距 `20px 24px`，模块间下外边距 `20px`。
- **状态卡片 (`.card`)**：内边距 `16px 18px`，网格间距 `16px`。
- **表格单元格 (`th`, `td`)**：水平边距 `14px`，垂直内边距 `10px`。
- **抽屉外框 (`details`)**：头部内边距 `13px 18px`，内容区内边距 `14px 18px 18px`。

## 4·5、数据排版（数字与数值列）

控制台是**数据面**：数字的可读性优先于正文观感。两条硬规则。

### 数字一律等宽（`font-variant-numeric: tabular-nums`）

在 `body` 上**全局声明**，不逐处写。

**为什么必须显式声明**：实测这台机器上，Segoe UI 的 **Regular(400) 与 Bold(700) 用等宽数字，
而 Medium(500) 与 Semibold(600) 用比例数字**（不同字重落在不同的字体文件上）。
也就是说，数字对不对得齐**取决于那个元素恰好用了哪个字重** —— 20px/700 的状态卡大数字是齐的，
而它下面 16px/600 的小数字、11.5px/600 的表头、600 的徽章**全都不齐**。
不声明就是在赌字体挑哪一套字形。

**不声明的代价**：数值刷新时位数一变（`9` → `10`），整段文字宽度跳变，表格跟着横向抖动。

### 数值列右对齐，表头跟着对齐

数值单元格与对应表头都加 `.num` 类（`td.num, th.num { text-align: right }`）。

**为什么不能直接对齐 `td.mono`**：mono 里混着**时间戳**和**模型 id** —— 那些是文本，
右对齐反而更难读。必须逐列标明，不能按字体一刀切。

**效果**：倍率列 `0.06 / 0.11 / 0.79 / 1.62` 的小数点对齐后，「哪个模型更便宜」
一眼可辨 —— 而这正是那张表要回答的问题。

### 验收

```cmd
node tools\dev\test-data-typography.mjs
```

它**直接量渲染宽度**（用克隆元素渲染 `1111111111` 与 `8888888888` 比宽度），
而不是查有没有写某个 CSS 属性 —— 写了也可能不生效。覆盖 9 类数字元素 + 3 张表的全部数值列。

> 注意：断言桩数据的字段名必须与真实接口一致。曾因为把 `/api/usage` 的 `models`
> 写成 `byModel`，导致用量表**静默地不渲染**，而页面看起来一切正常 ——
> 所有视觉检查都漏掉了那张表。见 `test-data-typography.mjs` 里的注释。

## 4·6、字体与字号（三层字体栈 + 六级阶梯）

### 三层字体栈：正文 / 中文 / 数据

全部用**系统自带**字体，不引外部 webfont —— 控制台是本地工具（`127.0.0.1`），
断网要能打开，而且它的定位是「凭据不出机器」，为排版去请求第三方字体服务不划算。

| 令牌 | 栈 | 用在哪 |
| :--- | :--- | :--- |
| `--font-sans` | `-apple-system` → `BlinkMacSystemFont` → `Segoe UI` → `PingFang SC` → `Hiragino Sans GB` → `Microsoft YaHei UI` → `Microsoft YaHei` → … | 正文、标签、按钮（拉丁走 Segoe UI / SF，中文由 CJK 回落接管） |
| `--font-mono` | `ui-monospace` → `SFMono-Regular` → `Menlo` → `Consolas` → `Courier New` | 模型 id、时间戳、数值、配置片段、日志 |

等宽这条栈**故意不加 Cascadia Mono**：它比 Consolas 整体宽约 7%，而模型表 9 列的宽度
预算已经卡死（见 6.11），多出来的宽度会直接变成折行与不齐的行高。

### 六级字号阶梯 + 一档密排档

相邻两级必须**看得出差别**，否则等于没有层级（上一版 10/10.5/11/11.5/12/12.5/13/13.5
八档挤在 3.5px 里，标签、说明、正文在页面上一样重）。

| 令牌 | 值 | 用在哪 |
| :--- | :--- | :--- |
| `--fs-micro` | 11px | 脚注、图例、角标、排序箭头 |
| `--fs-label` | 12px | 标签、徽章、时间戳、单位、次级说明 |
| `--fs-body` | 13px | 正文、表格、面板说明、按钮、下拉、输入框 |
| `--fs-lead` | 16px | 面板标题、客户端卡片名、无数字的读数 |
| `--fs-title` | 18px | 品牌标题 |
| `--fs-display` | 20px | 指标大数字 |
| `--fs-dense` | 11.5px | **密排档**：表头、等宽数据列、日志。它不参与层级，只解决表格宽度 |

`--fs-dense` 存在的原因是可量化的：模型表在 1280px 下的宽度预算刚好卡住，
表头回到 11.5px 才能让四行读数的行高一致（13px 表头会把 `DeepSeek-V4.1-Flash` 与
`0.0839 / 千 token（55 次）` 挤成两行，行高在 53～71px 之间跳）。

### 字重只用 400 / 600 / 700，**不用 500**

实测（Chrome + Windows）：**500 与 600 落在同一个字体文件**（同一串字符渲染宽度逐字相同），
而中文侧雅黑只有 Regular / Bold 两档 —— 500 归 Regular、600 归 Bold。
于是一条 500 的混排字符串会渲染成「拉丁偏粗 + 中文常规」：卡片标签「DSH 配置」里的
DSH 明显比中文重。层级只能靠 400（常规）与 600（强调）表达，700 留给大数字与品牌。

### 配套的观感规则

- **面板说明、对话正文按段落给行距**（1.6～1.7），不按控件密度给 —— 中文没有西文那样的
  上下伸部，行距不够整段会糊成一块。
- **小字中文给 `--track-label: 0.01em` 字距**：12px 密排时字挨字，一点字距才扫得动。
- **标题收紧 `--track-title: -0.012em`**：大字不能松。
- 成段文字加 `text-wrap: pretty`，避免段末把最后一个词组甩到下一行。
- 正文行高 1.6（`body`），表格本身不额外加行高。

### 验收

```cmd
node tools\dev\test-data-typography.mjs    # 数字等宽 + 数值列对齐
node tools\dev\test-viewports.mjs          # 四个宽度下无横向溢出
```

改字号后还要**量一次模型表的行高**（`#modelTable` 四行应等高）：字号变大最容易
先在这张表上变成折行。改前改后的对照可以用 `tools\dev\shot-regions.mjs` 出图。

## 5. 动效与交互规范 (Motion & Micro-interactions)

动效服务于界面的连贯感与操作反馈，杜绝拖泥带水。

### 5.1 物理缓动曲线与时间尺度

- **缓动曲线**：`--ease: cubic-bezier(0.16, 1, 0.3, 1)`（自然物理弹性回弹阻尼）。
- **极速响应 (Fast)**：`0.16s`，适用于按钮 hover、背景色渐变、文本高亮。
- **常规过度 (Normal)**：`0.22s ~ 0.24s`，适用于抽屉展开折叠、视图 Tab 切换、面板显隐。

### 5.2 方向语义：两条轴不能混用

位移方向本身携带信息，混用会让同一个动作被读成两种含义，动效就从信息变成噪音。

| 轴 | 语义 | 用在哪 |
|---|---|---|
| **横向平移** `translateX` | **平级切换** —— 「你在几个并列选项间移动」 | 页签、客户端选择器、面板切换 |
| **纵向平移** `translateY` | **层级展开** —— 「这里有东西长出来了」 | 折叠块、引导条、抽屉、表格详情 |
| **缩放** `scale` | **原地变化** —— 「这个元素本身的状态变了」 | 芯片勾选、按钮按下 |

> 芯片勾选用缩放而不是位移：位移会让相邻芯片看起来在重排，而实际上并没有。

### 5.3 伸缩动画：为什么用 grid 而不是 height / max-height

对「内容自适应高度」做伸缩，三种做法的取舍（**实测过，不是推测**）：

| 做法 | 结果 |
|---|---|
| `height: auto → 0` | ❌ 不可插值，硬切 |
| `max-height: 0 → N` | ⚠️ 能跑但节奏失真 —— 前 80% 的时长在走那段猜出来的空白 |
| `grid-template-rows: 1fr → 0fr` | ✅ **选它** |

`grid` 做法的两个必要条件，缺一不可：

```css
.wrap { display: grid; grid-template-rows: 1fr; transition: grid-template-rows .24s var(--ease); }
.wrap.closed { grid-template-rows: 0fr; }
.wrap > .item {
  min-height: 0;          /* 缺它轨道缩不到内容高度以下 */
  overflow: auto hidden;  /* y 裁剪是收缩前提；x 必须留 auto，否则长行看不全 */
}
```

> **踩过的坑**：`collapsed` 状态下如果还有一条 `display: none`（或任何把元素移出布局的规则），
> grid 伸缩会**完全失效** —— 类名在、样式却算成展开值，实测高度从 830px 瞬跳到 0。
> 折叠只能靠轨道高度，不能再动 `display`。
>
> 内边距也要一起收：只收轨道的话，折叠后仍会留 24px 空白（12px 上下内边距），
> 看起来像「没折干净」。

### 5.4 动效降级：`prefers-reduced-motion` 是必选项

系统里开了「减少动态效果」就把全部动画与过渡压到 `0.01ms`。
动效对本项目是锦上添花，但对前庭功能敏感的用户，位移与缩放会引起真实的不适。

- **只关「动」不关「变」**：状态变化照常发生，只是瞬间到位
- 用 `animation-duration: 0.01ms` 而**不是** `animation: none` —— 后者会让依赖
  `animationend` / `transitionend` 的逻辑收不到事件，反而制造新 bug
- 规则必须排在**所有动效之后**，靠后面的覆盖前面，顺序错了就失效
- 纯装饰的呼吸光晕可以直接 `animation: none`（状态由颜色本身表达，不依赖它）

### 5.5 微交互关键场景实现

1. **按钮反馈**：
   - 悬停：`transform: translateY(-1.5px)`，投影加深。
   - 按下：`transform: translateY(0.5px) scale(0.99)`，提供明确受压触感。
2. **抽屉栏展开 (Drawer Expand)**：
   - 箭头旋转：`<summary svg>` 保持 `transition: transform 0.24s var(--ease)`，展开旋转 `90deg`。
   - 隐藏浏览器原生黑三角：`summary::-webkit-details-marker { display: none !important; }`。
   - 抽屉内容淡入平移：`animation: drawerContentFade 0.22s var(--ease)`。
3. **表格展开详情抽屉 (`tr.detail-row`)**：
   - 内嵌卡片容器：`.detail-body` 采用 `border-radius: var(--radius)` 独立卡片化设计，伴随 `animation: detailExpand 0.22s var(--ease)` 平滑下移展开。
4. **运行状态呼吸光晕**：
   - 运行中绿色小圆点带有微弱脉冲光晕 (`@keyframes elegant-pulse`)，频率 2.2 秒。
5. **视图 Tab 切换**：
   - 激活项高亮突变，伴随面板内容微小向上淡入 (`@keyframes sectionFadeIn`)。

## 6. 组件设计规范详述

### 6.1 顶部品牌栏 (Header)
- 品牌图标：40x40 纯色皇家蓝底色，统一 12px 圆角，带有柔和蓝色立体投影。
- 状态胶囊：右上角展示健康度状态（`badge.ok` / `badge.fail`），统一胶囊圆角。
- 主题切换器与刷新按钮：统一 32px 紧凑高度，悬停平移微动效。

### 6.2 视图导航 Tab 切换器 (Nav Tabs)
- 外层容器：浅色边框与 12px 圆角包裹，内衬 4px。
- 选项卡：未激活时静止灰度，激活项 (`.nav-tab.active`) 采用纯正皇家蓝填充 (`--primary`)，白字白图标，搭配微投影，层级最高。

### 6.3 快捷操作栏 (Actions Bar)
- 工具条由「进程控制组」、「诊断复制组」与「实时状态消息」三段组成。
- 主操作按钮（启动桥/保存配置）使用 Solid Royal Blue，危险操作使用柔红底红字（悬停翻转为红底白字）。

### 6.4 HUD 核心指标卡 (Cards)
- 4 列自适应网格，右上角配一枚 **26px 语义色底衬图标**（`16px` 描边图标 + `5px` padding）。
- **图标颜色承载语义，不是清一色主色**（由渲染层 `card(key, value, note, small, tone)`
  的第五个参数给出；**不参与任何判断**，不传则退回主色）：

  | tone | 色相 | 用在哪 |
  | :--- | :--- | :--- |
  | `tone-ok` | 绿 | 桥进程（运行中）、DSH 已就绪、凭据已加密、令牌余量充足（> 30 天） |
  | `tone-warn` | 琥珀 | 积分余额（额度）、令牌 30 天内到期 |
  | `tone-fail` | 红 | 桥未运行、令牌 7 天内到期 |
  | `tone-info` | 青 | 上游端点（**远端**，与本地蓝系在色彩上分开） |
  | `tone-primary` | 蓝 | 可用模型（本地目录） |
  | `tone-muted` | 灰 | 账号等纯标识信息 |

- **底衬还解决了一个配重问题**：原先右上角是 16px 细线图标，与左下角 20px/700 的大数字
  完全不配重，整张卡左重右空。加了底衬，右上角才有实体。
- 悬停时边框切换为主色蓝，卡片向上浮动 2px（`--shadow-lift`），图标放大 1.08 倍。
- **卡片顺序本身就是层级**（见 6.10），不靠把某个数字放大来强调。

### 6.5 数据表格与模型列表 (Table & Model Table)
- 外包裹器严格统一切圆角（12px），表头 sticky 固定，背景与边框色彩分明。
- 行选中态（勾选 checkbox 或点击联动）：整行附加 `rgba(37, 99, 235, 0.035)` 微弱蓝色底色，与未选中行区分清晰。
- 详情展开行：独立嵌套为 12px 圆角的浮层卡片，消除以往表格下沉断裂感。

### 6.6 抽屉栏组件 (Drawer Bar)
- `details`/`summary` 统一设计为带 12px 圆角的抽屉条。
- 默认收起态为紧凑的一体化灰色横条，悬停蓝色高亮；
- 展开态下边框高亮为蓝色细线，内部集成操作栏与独立终端暗色输出容器。

### 6.7 面板结构：标题行与工具行分开
- **标题行只放「标题 + 更新时间戳」**。下拉、按钮、长提示**不得塞进 `<h2>`** ——
  一行放不下就乱换行，标题与控件抢同一条基线，读的人分不清哪部分能点。
- 有控件时用 `.panel-tools`（标题之下、内容之上的一行）：提示靠左，`.spacer` 撑开，
  控件右对齐成一组。用量统计面板是这套的标准样板。

### 6.8 反馈必须出现在用户动作的位置
- **复制类动作走就地反馈**：值闪一下（`.copied` / `.copyfail`）或按钮文案变「已复制」，
  外加 aria-live 播报；**只有失败才升级到顶部提示条**。
  理由实测过：模型表在页面约 60% 处，滚到那里点复制时顶部提示条的 `top = -1873px`，
  完全在视口外 —— 只靠提示条等于没有反馈。
- **aria-live 播报区必须在任何 `data-section` 之外**（`#liveRegion` 挂在 `.wrap` 顶层）。
  它原先藏在「客户端接入」面板里，而切到别的页签时该面板是 `display:none` ——
  不可见子树里的 aria-live 不会被朗读。`test-clients-panel` 已把这条钉成断言。
- **可点击的单元格必须键盘可达**：格子里放真 `<button>`（外观可以仍然像一格文本），
  不要只写 `<td onclick>`。冒泡到同一条 handler，鼠标点整格与键盘 Enter 共用一个入口。
- **数据变化要留痕**：轮询换掉的读数给一次 0.6s 底色脉冲（`.card .v.bump`）；
  **首帧没有基线不脉冲**，否则每次进页面整排卡都在闪。

### 6.9 过渡的三条规矩
1. **状态变化一律有过渡**：hover、激活、显隐，以及**禁用态**——禁用靠 `opacity` 表达时，
   `opacity` 必须出现在 `button` 的 transition 列表里，否则启停桥后那一跳是硬切。
2. **出现与收起成对**：只有 `slideDown` 而没有收起动画，效果就是「瞬间消失 + 下面内容上跳」，
   用户分不清是自己关掉的还是页面刷了。收起统一用 `collapseAway()`（高度 + 淡出 180ms，
   收完再落状态；时长刻意压短，不挤掉 `test-r3-alerts` 点完 250ms 的断言窗口）。
3. **整页级切换交给平台**：主题切换与语言切换都是「整页状态换一次」，
   走 **View Transitions API**（`withViewTransition()` 包住状态变更，浏览器自己
   交叉淡化旧/新两帧）。**不要**自己拼：全局 `*` 过渡要处理「挂 class → 强制回流 →
   再改值」的顺序陷阱（漏一步动画静默失效）、`box-shadow` 一加进去就会因为
   每帧插值 1200+ 个元素的阴影把补间压成一帧、两段式还要 JS 计时器与 CSS 时长对齐。
   面板首次填充淡入仍由 `initPanelFadeIn()` 判断「占位符 → 内容」那一次，轮询重绘不触发。
4. **降级要能落地**：没有 `startViewTransition` 时**直接改状态** ——
   动画是装饰，状态不能因为动画而丢。
5. **不重复补间**：整页淡化已经覆盖的东西（主题按钮里的太阳/月亮图标）
   不要再写一层自己的 opacity 补间，那会把「点下去到看见变化」拆成两段。
6. **动效要按机制验收，不是读代码**：断言 `startViewTransition` 真的被调用（spy）、
   过渡期间存在 `::view-transition-old/new(root)` 的伪元素动画**且 currentTime 在推进**
   （只有动画对象、不推进等于没动）、状态落点正确、降级路径仍然能切。
   参考 `tools/dev/test-transitions.mjs`。
   取样注意：伪元素动画是**下一帧**才建的，点击后立刻读会拿到空数组。

全部动效仍受第 18 节 `prefers-reduced-motion` 覆盖（它必须排在所有动效规则之后）。
例外是整页交叉淡化：它是**透明度**不是 motion，reduce 下保留（只把时长压到 120ms）——
对关掉系统动画的人，「颜色瞬间翻转、全页文字瞬间替换」会被读成「页面闪了一下/坏了重绘」。

### 6.10 状态读数卡的顺序 = 层级
按「第一眼要回答的问题」排：**在跑吗 → 有多少能用 → 还能用多久 → 还剩多少额度 →
dsh 接好了没 → 标识信息（账号 / 加密方式 / 端点）**。
卡片字号与样式保持等权，**顺序本身就是层级** —— 不需要靠把某个数字放大来强调。

### 6.11 模型表的列宽与折行
- 短内容列（上下文 / 最大输出 / 倍率 / dsh / 可用性）`white-space: nowrap`；
- 模型 id 列 `min-width: 148px`；
- 这张表的横向内边距单独收到 **9px**（不是全局 14px）—— 9 列 × 14px 会把约 250px
  花在 padding 上，挤得 id 与「实测成本」折行，行高在 53～89px 之间跳。
- 目标：1280px 视口下**所有数据行等高**。改表结构后重新量一次行高。

## 7. 规范落地检查清单 (Checklist)

开发或修改任何前端功能时，必须逐项核对：
- [x] **色彩检查**：主强调色是否严格为 `--primary`（皇家蓝）？是否存在任何随意硬编码的渐变？
- [x] **圆角检查**：圆角是否严格使用 `--radius-xs`, `--radius-sm`, `--radius`, `--radius-lg`, `--radius-full` 之一？
- [x] **抽屉检查**：所有展开折叠栏（包括日志抽屉、表格详情抽屉）是否拥有统一的 12px 圆角与柔和动效？
- [x] **间距检查**：组件 paddings 与 margins 是否为 4/8/12/16/20/24px 网格倍数？
- [x] **动效检查**：所有可点击控件是否配置了物理缓动过渡，避免突兀切换？**禁用态（opacity）算不算在内？**
- [x] **成对动效检查**：有出现动画的块，收起是否也有动画？内容首次到位是否有淡入（且轮询重绘不重复）？
      **主题切换与语言切换这两处「整页级」变化走的是 View Transitions 吗？**（按机制验收：spy 到调用 + 伪元素动画在推进 + 降级路径仍能切，别读代码猜）
- [x] **反馈位置检查**：复制 / 保存这类动作，反馈是否出现在用户点击的地方？aria-live 区是否不在被隐藏的子树里？
- [x] **键盘可达检查**：新增的可点击单元格 / 自绘控件是否是真正的 `button`（或有 `tabindex` + `:focus-visible`）？
- [x] **表列折行检查**：短内容列有没有被挤到折行、导致行高不齐？改表后量一次行高
- [x] **深色模式检查**：暗色下所有文本与表面对比度是否清晰，无过曝或死黑？
- [x] **数据排版检查**：新增的数值列是否加了 `.num`（表头也要）？新增的数字元素是否继承了 `tabular-nums`？跑 `node tools\dev\test-data-typography.mjs` 验证
- [x] **字号检查**：新增的文字是否用了 `--fs-*` 里的档位（不要写新的 px 字面量）？字重是否只用 400/600/700（**500 是个空档位**）？改过字号后，模型表的行高是否仍然等高（`#modelTable` 四行应齐）？
- [x] **对比度检查**：新增的文字颜色是否 ≥ 4.5:1（WCAG AA）？说明类文字用 `--hint` 而不是 `--faint`（后者只有 2.45:1）
- [x] **语义色检查**：新增的指标卡 / 状态图标，颜色是否**承载了语义**（`tone-*`）而不是一律主色？新加的语义色与既有的 ok/warn/fail/promo/info 是否都不撞？
- [x] **阴影检查**：新增的浮起层是否用了分层阴影令牌（`--shadow-*`）？有没有只靠 1px 边框撑层次？可点卡片的悬停用 `--shadow-lift`，日常面板**不要**加悬停抬升
- [x] **渐变检查**：若用了渐变，是否**只有同一色相内的明度变化**、且只落在实心色块或图表柱体上？有没有不小心做成多彩渐变？
