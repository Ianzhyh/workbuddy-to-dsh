# 插件面板 ⇄ 控制台 功能对照

用户要求：「两边插件面板进度要同步，不然万一漏了」。
后来又明确：「**控制台功能对齐插件里面功能**」。

做法：**把"哪边有什么"固化成一张表**，并写一个脚本自动核对 ——
新增功能时先加一行，脚本会告诉你另一边还缺什么。

## 明确的"故意不同"

这几项**不该**同步，写下来避免以后被当成漏项：

- **模型测速的入口位置**：插件侧只测「当前默认模型」（右栏太窄，逐行按钮会
  让误点成本变高）；控制台是表格，逐行给按钮才合理。**测速规则完全一样**
  （三次取中位数、丢弃过短样本、绝不外推、结果不落盘、桥侧 30 分钟缓存）。
- **隐藏未列出的默认值**：插件侧默认「未列出的不进 dsh 选择器」（那是路由
  行为）；控制台侧默认**全显示**，只提供一个可勾选的收窄开关（那是"看数据"）。
  两者的 `official` 判定同源（桥目录字段）。
- **对话测试的模型下拉与历史**：各存各的内存态，不跨端同步（一个是页面级状态，
  一个是 React 组件状态；同步反而会互相把对方的选择冲掉）。**三项采样参数两边都
  有，语义完全一致**（留空 = 不发该字段，绝不替用户猜默认值）。
- **网页搜索（状态 / 一键接入 / 恢复接入前配置）**：那改的是 **dsh 自己的
  `web-search-deepseek` 分节与独立凭据引用** —— 控制台不在 dsh 里，拿不到 settings /
  credentials 服务，做不了也不该做。控制台只负责桥这一侧（`POST /v1/web_search`
  在「客户端接入」里说明）。
- **按模型的上下文预算（dsh context budget）编辑**：写的是 dsh 的每模型参数
  （`contextWindowByModel`），属于"驱动 dsh 怎么发请求"。控制台是**只读展示**
  该模型的官方默认 / 上限 / 可选档位（模型详情里），改动在 dsh 面板做 —— 与
  README 里「按模型的输入/输出 Token 编辑在 dsh 插件面板」一致。
- **待办提醒的触发项**：控制台是「桥不可用 > 令牌临期 > 新失败 > 未签到」，
  插件多了「路由未注册 / 有旧路由」两项目——那两项在控制台侧由**诊断面板**
  用同一套 `lib/diagnostics.mjs` 判定并给出修法，不必再进顶部提示条（顶部只放
  "现在就得动手、且能就地处理"的事）。

## 为什么把规则抽成 `lib/limits.mjs`

「哪个账号的哪个模型触顶了」这张表的四类规则——分类（quota / credits /
account_restricted / rate_limit）、历史合并（空 `resetAt` 不能覆盖已知值）、
恢复时间三层兜底（health 结构化字段 → health 文案 → 失败账本原文）、
过期清理（到点 / 无时间最多留 7 天）——**两边各写一遍必然漂移**。

漂移的后果不是"少个功能"，而是**两边给出互相矛盾的结论**：控制台说
「额度已用尽」、面板说「没有账号触顶」，用户只能两边都不信。所以规则收进
`lib/limits.mjs`（纯函数 + 一份落盘读写），插件侧 `dsh-plugin/lib/index.js`
与 `dashboard/server.mjs` 都从这里取。

`dsh-plugin/tests/reset-time.test.mjs` / `limit-history.test.mjs` /
`limits-route.test.mjs` 与 `lib/limits.test.mjs` 分别钉住两侧的行为；
`tools/dev/test-parity-console.mjs` 钉住控制台界面上那三句不同结论。

## 核对方式

```sh
node tools/dev/check-parity.mjs                 # 两端实现痕迹
node tools/dev/test-parity-console.mjs          # 控制台侧界面结论（无头浏览器）
node tools/dev/test-chat-params.mjs             # 对话采样参数（留空不发 / 非法拦住 / 档位跟模型）
node tools/dev/probe-console-live.mjs           # 对着**真实实例**跑一遍（真接口 + 真渲染）
node --test "lib/limits.test.mjs"               # 共用规则本身
npm run vendor                                  # 把 lib/limits.mjs 同步进插件 vendor/
```

`check-parity.mjs` 读 `tools/dev/parity.json` 里的清单，检查每项在两边的实现痕迹
（标记字符串）是否存在，缺哪边就报哪边。
