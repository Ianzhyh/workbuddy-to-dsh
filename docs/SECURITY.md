# 安全与合规

## 信任边界

本项目**只在本机回环地址上工作**：

```
127.0.0.1:8790   桥（OpenAI 兼容接口）
127.0.0.1:8792   控制台（管理界面）
```

两者都不接受外部连接。项目中没有、也不应有任何把监听地址改为 `0.0.0.0` 的配置项
（`.env.example` 与代码注释中均明确标注了这一点，因为那会把你账号的模型额度
暴露给能访问该端口的任何机器）。

---

## 明确不做的事

| 不做 | 原因 |
|---|---|
| **不内置任何密钥** | AtRest 字段密钥每次从写入登录文件的那个客户端现取；项目内不存在密钥副本 |
| **不落盘令牌** | 令牌只在内存中解密后用于构造请求头，不写文件、不写日志 |
| **不写回登录文件** | 登录文件是客户端的加密存储，写入明文会破坏它。刷新结果只留在桥进程内存中 |
| **不记录对话内容** | 开启日志时只记录模型名、消息数、工具数 |
| **不绕过鉴权** | 只驱动使用者**自己已登录**的账号；不提供、也不接受任何绕过认证的手段 |
| **不外发数据** | 除发往 WorkBuddy 上游（`copilot.tencent.com`）的模型请求外，无任何遥测或回传 |

## 凭据是如何被处理的

```
WorkBuddy.exe（以 ELECTRON_RUN_AS_NODE 运行）
        │  返回 { atRestSecretKey, ... }        ← 只读客户端自述，不落盘
        ▼
   SHA256 → 32 字节字段密钥（进程内缓存）
        │
        ▼
   解开 envelope → 明文 JWT（仅存在于内存）
        │
        ▼
   Authorization: Bearer <jwt>  ──►  copilot.tencent.com
```

诊断功能（控制台页面、`tools/doctor.mjs`）会读取凭据，但**只用于判定**，
返回结构里只有：

- 令牌**长度**（用于确认非空且形态正常）
- 是否以 `eyJ` 开头（用于确认是 JWS 而非解密失败的产物）
- 账号 uin、有效期、`keyId` 是否吻合

控制台的 API 响应中**不包含任何令牌片段**。`.credentials.yaml` 也只读取键名、不读值。

## 你会看到的敏感信息

以下文件**包含有效凭据**，请勿提交、勿分享、勿放入备份同步目录：

| 文件 | 内容 |
|---|---|
| `%LOCALAPPDATA%\CodeBuddyExtension\Data\Public\auth\*.info` | 加密后的 access/refresh token |
| `~/.dsh/.credentials.yaml` | 各 provider 的 API key（含本项目写入的占位值） |
| `~/.workbuddy/keyblob` | 客户端主密钥的包裹信息 |

`.gitignore` 已排除 `*.info`、`.env`、`*.bak-*` 等模式。

> 本项目写入 `.credentials.yaml` 的值是**本地回环占位串**（默认 `wb-local-bridge`），
> 不是上游凭据——它只用于满足 dsh 侧"必须提供 API key 引用"的要求。

## 风险声明

1. **非官方路径。** 本项目通过客户端的公开原生接口与上游网关通信，属于互操作性实现。
   上游随时可能修改协议或封禁该方式，**可用性无任何保证**。
2. **服务条款。** 使用前请自行确认符合你与 WorkBuddy 之间的服务条款。把账号额度
   转供给其他程序使用，可能触及你所在环境的合规要求。团队或商用场景，正确做法是
   申请官方 API 访问权限。
3. **额度归属。** 桥消耗的是你自己账号的配额。控制台的「对话测试」同样会消耗少量额度。
4. **无担保。** 按 MIT 许可，本软件"按现状"提供，不附带任何明示或暗示的担保。

## 建议的使用姿势

- 保持 `127.0.0.1` 绑定，不要为了"方便其它设备访问"而改成 `0.0.0.0`
- 不要长期高频自动化调用——既无必要，也更容易触发上游风控
- 换机器或重装客户端后，重新登录一次即可；不需要手工搬运任何凭据文件
- 若不再使用，删掉 `~/.dsh/settings.yaml` 中本项目生成的分节即可，桥本体无残留
