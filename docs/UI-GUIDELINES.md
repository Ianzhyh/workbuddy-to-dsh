# 控制台界面规范（UI Guidelines）

> 适用范围：`dashboard/public/`（网页控制台）与 `dsh-plugin/` 里的设置页。
> 这份文档是**可执行的检查清单**，不是审美散文 —— 每一条都能在评审时当场判定。
>
> 来历：2026-10-10 评审了本机另一个前端项目（`D:\IANMUSICD\melodix`，见
> `D:\IANMUSICD\DESIGN-REVIEW.md`）之后，把它那份 HIG 里**真正能落地**的部分
> 搬到我们的场景里 —— 加上我们自己的实测教训（下面标了「本项目实测」的都是踩过的）。

---

## 0. 评审时只用这三句话

遇到"这个界面够不够好"的争论，别比谁的形容词更高级，用这三个判据：

1. **竞争测试**：屏幕上如果有两个元素在抢注意力，**必有一个是错的** ——
   要么降低不重要的那个的权重，要么把它们分到不同的区（加间距）。
2. **眯眼测试**：眯眼看屏幕直到读不出字。如果作为一堆抽象色块与留白仍然平衡，
   布局就对了；如果像贴满告示的公告栏，就是留白不够。
3. **日光灯测试**：这个新组件像这间屋子里本来就有的东西，还是像有人拖进来一盏办公室日光灯？

---

## 1. 颜色：90 / 5 / 5

任何一屏的颜色配比：

- **90% 中性**：`--bg` / `--panel` / `--panel-muted` / `--border` 这一族，靠细微差别分层。
- **5% 品牌色**：`--primary` 只用于**激活态、选中项、主按钮**。
  一屏里主色面积超过 5% 就是滥用了 —— 主色一多，"哪里是重点"就消失了。
- **5% 语义色**：`--ok` / `--warn` / `--fail` / `--info`（含 `-soft` 底、`-border` 边）。

**规矩**：

- 语义色只表达**状态**，不用来装饰（"这个卡片配个绿色好看"→ 不行，用户会以为它表示正常）。
- 深色主题下**白色文字不要用纯白**：用 `--text`（0.95 那一档）而不是 `#fff`，长时间盯着不刺眼。
- 文字层级只用四档：`--text`（标题/正文）→ `--text-secondary` → `--muted`（说明）→ `--faint`（时间戳/占位）。
  **不要临场调 opacity 造第五档** —— 那会让同一层级的文字在不同面板里深浅不一。

---

## 2. 排版：字阶是封闭集合

**文字**字号**只准**用这 7 个令牌（`--fs-micro` / `--fs-label` / `--fs-body` / `--fs-lead` /
`--fs-title` / `--fs-display` / `--fs-dense`），行内 `style={{ fontSize: 13 }}` 这类写法一律不收。

> 例外：**纯装饰性图形**不受此限（例如请求活动指示器的 3 个点用 `10px`）——
> 它不是文字，不参与字阶的层级关系。有例外就写在注释里，别让人以为是漏改。

- 大字**收字距**（`--track-title`）、小字**放字距**（`--track-label`）：
  大字松、小字挤是排版里最常见的"说不上哪里不对"。
- **本项目实测：字重只用 400 / 600 / 700，不要用 500**。
  这台机器上（Chrome + Windows）500 与 600 落在**同一个字体文件**里（渲染宽度逐字相同），
  而中文侧雅黑只有 Regular / Bold 两档：500 归 Regular、600 归 Bold。
  于是一条 500 的混排串会渲染成"拉丁偏粗 + 中文常规"，看着像两种字体没对齐。
- **截断纪律**：表格单元格、路径、模型名一律 `nowrap + ellipsis`，
  **绝不允许换行把行高撑起来**。行高参差是列表最显廉价的毛病。

---

## 3. 层次：阴影要分层，玻璃要有清单

- 浮层用**两层阴影**（紧的 + 散的）：`--shadow-card` / `--shadow-panel` / `--shadow-drawer` 已经这么配了。
  单层淡影在 1x 屏上几乎看不见，整页层次会全靠 1px 边框撑着 —— 那看起来像"画在纸上的方框"。
- **禁止硬阴影**（`0 2px 0 #000`）。
- 浅色模式的阴影用**带色调的深色**（我们的 `--shadow-*` 已是 `rgba(15,23,42,…)`），不要纯黑。
- 玻璃面板（`backdrop-filter`）必须齐四项：
  低 alpha 底 + `backdrop-filter`（**含 `-webkit-` 同款**）+ 一道细微高光边框 + 圆角。
  缺哪一项都会露馅（尤其漏 `-webkit-`：WebView2 / Safari 上直接变成一块死色）。

---

## 4. z 轴：只准用令牌

**只准**用 `--z-table-head` / `--z-float` / `--z-sticky` / `--z-dropdown` / `--z-tooltip` /
`--z-overlay` / `--z-toast`，**不要再写裸数字**。

理由是本项目实测出来的：原先 5 处 z-index 是随手写的（2 / 80 / 99 / 100 / 200），
其中**下拉菜单 80 低于吸顶工具条 100** —— 顺序本身就是错的。
现在恰好没有"从顶栏里展开的下拉"，所以还没暴露；但顶栏里加一个下拉就会中招，
而且这种覆盖错**读代码看不出来**（两个数字隔了 600 行）。

新增浮动层时先问一句：**它可能出现在谁的上面？** 然后挑对应那一档；挑不到就说明该扩这个阶梯，而不是写个数字。

---

## 5. 加载、空态与失败：三种状态都要设计

1. **加载态**：**永远不要给用户一块空白**。用 `.skeleton` 骨架屏给**结构预览**
   （几根长短不一的条 = "这里会出现一张表"），不要只放一句「正在读取…」——
   静态文字既看不出将要出现什么，也分不出"在读"和"卡住"。
   - 骨架屏要保留 `role="status"` + `aria-label`（文案进词条表），读屏用户才知道在读；
   - 动画走 `background-position`（不触发重排），并**尊重 `prefers-reduced-motion`**：
     动效不是信息，晕动症用户不该被迫看它。
2. **空态**：说清"为什么空"和"下一步做什么"（`还没有请求记录。` → 好过 `暂无数据`）。
3. **失败态**：给**原因 + 处置**，而且要用**可操作**的措辞。
   本项目的规矩是"界面不说假话"：读不到就说读不到，桥没起和令牌被拒要分开说
   （前者去点启动桥，后者去重启桥 —— 混成一句用户会按错按钮）。

---

## 6. 动效：先问"改的是颜色还是几何"

**只允许用 CSS transition 的属性**（`--transition-fast` / `--transition-normal` 已按此设定）：

| 属性 | 时长 |
|---|---|
| `color` / `background-color` / `border-color` | 200ms |
| `opacity` | 150–300ms |
| `box-shadow` | 200ms |

**其余一切**（位置、尺寸、transform、布局）走 `--ease` 曲线，且：

- **退场要比入场快**（入场 ~300ms、退场 ~150ms）—— 慢吞吞的关闭动画是最容易被感知为"卡"的地方；
- **尊重 `prefers-reduced-motion`**：把位移/缩放换成纯透明度变化；
- 列表/表格的**首次出现**可以错峰（每项 ~30ms），但**上限 ~15 项**，超出的一起出现 ——
  否则用户要等一秒才看全。

**不要用动效表达"我在忙"**：那是骨架屏与进行中状态的职责（见第 5 节）。

---

## 7. 每个可交互元素都必须有这 6 个状态

| 状态 | 表现 | 我们已有的实现 |
|---|---|---|
| Idle | 基础样式 | — |
| Hover | 底色变化（`--panel-hover` / `--primary-hover`） | — |
| Active/Tap | 按下态（`--primary-active`）或轻微缩放 | — |
| **Focus** | **主色描边环** | `:focus-visible` + `--ring`（鼠标点击不显示） |
| Disabled | 降透明度 + `cursor: not-allowed` | `button:disabled` 全局兜底 |
| Loading | 进行中标记（禁用 + 文案/骨架） | `.connectbusy` 之类 |

**验收方式**：键盘 Tab 走一遍你要交付的界面 —— 焦点走到哪都要看得见，且顺序与视觉顺序一致。
这一条能一次性消灭"点了没反应""键盘走不到""焦点丢失"三类问题。

---

## 8. 双语与数据边界（本项目特有，别的项目没有）

1. **界面文案必须进词条表**：新增中文串后跑 `npm run check:i18n`，
   英文模式下**一个字都不许剩**（面板用例会扫 `#clientsBox` 里的可见中文）。
2. **上游数据不进翻译层**：模型名、路径、错误原文、日志行都是**数据**，
   要么单独成节点、要么标 `data-i18n-skip` —— 否则英文模式下会被逐字扫描，既翻不动又白费。
3. **动态值不要拼进整句**：`'原文件已备份到：' + path` 这种拼法，
   在切到英文后那一行会永远留中文（翻译层认不出整句了）。
   正确形状是 `{prefix, data}` 两个节点（前缀可翻、原文不翻）——
   本项目实测踩过，见 `connectResultLines` / `connectLine`。
4. **报错不许出现凭据明文**：只允许长度、账号、有效期、keyId。

## 10. 与 `melodix` 的差异（为什么没有全盘照搬）

| melodix 的做法 | 我们的选择 | 原因 |
|---|---|---|
| 深色为主 + 封面驱动的动态主色 | 浅色为主，主色固定 | 控制台是**工具**不是**氛围**：颜色在这里承担"状态"语义，动态色会让"主色 = 可点/激活"这条约定失效 |
| 三级玻璃（Heavy/Medium/Thin） | 只在浮层与提示上少量用 | 控制台一屏的信息密度高，大面积 `backdrop-filter` 会拖慢滚动且降低文字对比 |
| 弹簧物理动效（framer-motion） | CSS transition + View Transitions | 零依赖是硬约束（本项目不引第三方运行时）；`prefers-reduced-motion` 下更好收口 |
| 大字号阶（32/24/17…） | 更小更密（含 `--fs-dense` 11.5px） | 控制台要在 1280px 里塞 9 列表格，字号阶要为**宽度**让步 |
| 全局 `user-select: none` | 保留可选中 | 用户要复制令牌、路径、报错原文 |

**结论**：借的是**方法与纪律**（配比、标尺、状态清单、动效边界、评审测试），不是它的皮。

| 颜色配比 90/5/5 | ✅ 目视 + 截图 | 主色只出现在激活态、主按钮、状态标签上；卡片/表格/正文全中性 |

**结论**：控制台在这份清单上**原本就已经相当自律**（字重、字号、动效降级、i18n 数据边界都过了），
真正查出来的 4 条都是"**没人写下来过、所以没人定期看**"的那一类 —— 这正是规范存在的意义。

**还差什么**（留给下一轮）：几何属性的动效目前是 CSS transition（150–300ms ease），
规范允许但要**显式列属性**（已做到）；若哪天想要"弹簧感"，CSS `linear()` 可以零依赖近似，
**但那属于观感升级，不是缺陷** —— 别为了对齐别人的规范而改自己的产品。
