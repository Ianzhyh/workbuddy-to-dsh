## 过程中发现并修掉的 5 个缺陷（都不是最初计划里的）

这轮优化的实际价值大头在这里 —— **每个都是真 bug，且都由"追问边界"而非"确认已写的逻辑"暴露出来**。

### 1. D3 误杀（独立验证者发现，Lead 复现，已修）
预校验用 `catalogCache.models.length === 0` 判断"目录未知"，但缓存是 **FEATURED 补全后**写入的，
且只在硬失败（5xx/网络异常）时跳过写入。于是"目录端点 404 / 返回空数组 / 模型全被过滤"
这类**非 5xx 的拿不到目录**，缓存都会被填成"至少 3 个 FEATURED"→ 预校验被误激活
→ 任何不在 FEATURED 里的**真实可用模型**被本地 400 拦下，**一次上游都不打**。

6 个现实场景中 **5 个误杀**；新旧对照确认是本次引入的回归（HEAD 转发 200 → 本版 400）。
**修法**：新增 `catalogCache.upstreamModelCount`（FEATURED 补全**之前**计数，
写缓存时排除 `_supplemented` 项），预校验唯一启用条件是它 `> 0`。
FEATURED 仍参与**放行**、但不参与**激活**。

### 2. D3 的连带：`upstreamOk` 不能直接用（实现者发现）
`upstreamOk` 在端点回**空数组**时也是 `true` —— 它的语义是"这次刷新算不算成功"，
服务于 `/v1/models?refresh=1` 的 staleMs 提示，与"桥认识几个模型"不是一回事。
因此必须引入独立判据，而不是复用现成变量。

### 3. D2 的 413 被 RST 吞掉（独立验证者发现，已修）
`req.pause()` 后客户端还在发，而 413 分支在 `res.end()` 后 `req.destroy()` ——
内核回 RST，客户端在读到 413 前就 `ECONNRESET`。实测 1MB 1/10、8MB 4-6/10、16MB 9/10。
**修法**：改用 `req.resume()` 读掉并丢弃剩余字节，让连接自然收尾。
实测 ~17/50 → **1/150**，且残余丢失经归因确认是客户端收尾竞态（服务端 40/40 全部正确记录）。

> 注意：实现者第一版修法是"写完 413 再 destroy"，**仍然是错的**（8MB 10/10 丢失）——
> 说明这条必须靠实测而不是推理来确认。

### 4. 控制台调度器：初始隐藏时定时器永不恢复（Lead 复审发现，已修）
`resumePollsNow()` 里 `if (wasRunning) startPolls()` 的守卫，把"页面一开始就隐藏
（后台标签页打开 / 浏览器恢复会话）"这条**正常路径**一起挡掉了：切回可见时补了一次数据，
但**定时器永远不启动**，此后页面静默停更且不报错。比"多轮询"严重得多。
**修法**：无条件 `startPolls()`（其自带幂等保护），并补了专门的回归测试。

### 5. 事件风暴：切一次标签页补多轮全量请求（实现者自查发现，已修）
监听了 4 个事件（visibilitychange/focus/pageshow/blur），而每次 sync 都补一轮数据 ——
浏览器切一次标签页常派发多个事件，于是**比不做门控更费**。
**修法**：调度器内部记 `lastHidden`，状态没翻转直接 return。

### 附带修复
- **D4 回归**（实现者自查）：沿用 `size < usageBytes` 判据时，文件被删除后 `usageBytes` 归 0，
  `size < 0` 恒 false → 外部换入的任何文件都触发不了重载，镜像**永久失配**。
  改用**文件指纹（字节数 + mtime）**判据，`probe-d4-accounting` 6/7 → **7/7**，
  且"外部换入更大文件"从"读到 0 条"变成"读到 50 条"（**优于 HEAD**）。
- **`:790` 误命中 `:8790`**：`findPortPid` 原用 `line.includes(':PORT')`，
  找 79 会命中 `:790`。改为列级 `endsWith(':PORT')`。
- **import 即 listen**：`dashboard/server.mjs` 原来 import 就起服务，
  导致 `node --test` 子进程挂着一个永不关闭的 socket、**永远不退出**（只报一句笼统的
  "test failed"）。加 `isMainModule()` 守卫，并实测 `node dashboard/server.mjs` 仍正常启动。

## 已知边界（诚实记录）

1. **D2 残余 1/150 丢失**：极端负载下客户端收尾仍有竞态。服务端侧确认正确
   （40/40 全部正确记录并拒绝），不再进一步修。
2. **D5 的收益未能量化**：异步化确实生效（轮询期间心跳全 ~30ms），但无法构造
   "端口长时间不释放"来证明最坏路径的改善。**正确性无破坏、返回结构未变**，
   `netstat` 参数收窄是明确正向改进。标注为 **[存疑]** 而非宣称收益。
3. **`size/mtime` 指纹的既有语义**：外部换入**更大**文件现在会重载（比 HEAD 好），
   但这属于语义变化，已在测试中钉住。
4. **README 截图是非确定性产物**：`npm run panel:shot` 连跑两次 SHA256 不同
   （含 `Date.now()` 时间戳 + 实时数据）。任何人跑一次都会得到"脏工作区"。
   本轮已还原。**建议后续**：把该脚本产物输出到 gitignore 位置，或在文档注明"跑完请还原"。

## 附：折线图与长度变化动效全面打磨（2026-10-05）

**折线图切换生硬突兀（大幅度跳变）的彻底根治：**

- 引入 `getCurvedPath(pts)` Catmull-Rom → 三阶贝塞尔样条曲线算法（张力 0.18），所有数据点间形成柔和的水波弧度，彻底消灭硬折角与尖刺。
- 顶部 18% 呼吸裕度（`max = ceil(rawMax × 1.18)`），防止峰值撞顶突兀。
- 移除圆点的横向位移补间（`cx/cy transition`），统一由底基准线微升渐现（`.wb-curve-enter`，`opacity 0.12→1` + `scaleY(0.93→1)`，0.32s），根除切换时圆点横冲直撞的视觉噪音。

**全局筛选引起的长度变化补齐平滑过渡：**

- `ModelBarChart` SVG `<rect>` 柱长补齐 `cubic-bezier(0.16,1,0.3,1)` 缓动（修复 SVG 属性无法触发 CSS transition 的渲染痛点）；
- `ModelProportionBar` 彩条宽度升级为同款缓动，排序稳定化防止切换指标时色块乱换位；
- 积分套餐进度条 `.wb-bar i`、明细表迷你占比条全部统一为 0.45s 贝塞尔缓动 + `will-change: width`；
- 相应 CSS 类 `.wb-bar-rect` 补充统一，`@media prefers-reduced-motion` 全部关闭。
